## 1. Architecture summary

pHloat is a two-tier ESP32 fermentation monitor. Battery **pH sensors**
(ESP32-S3 + Atlas Scientific pH circuit) read pH once a minute and send it over
**ESP-NOW** (no WiFi) to a mains-powered **relay** (ESP32). The relay stores
readings in SPIFFS, serves a local web UI on port 80 for config/calibration/data,
and forwards each reading over WiFi as an HTTP POST to a configurable **upload
endpoint** — either a **Google Apps Script** web app that writes to Google
Sheets, or a **Tilt Pi** Flask server (`tiltpi/phloat_server.py`) that stores to
SQLite, matches each pH reading to the nearest **Tilt hydrometer** reading by
timestamp (±60 s), and optionally re-uploads to Google Sheets. All three upload
consumers share one contract (`integration/upload_contract.json`): a JSON body
and an `X-pHloat-Token` auth header. The relay web UI gates *write* endpoints
with an `X-API-Key` header; the Tilt Pi server gates only `/api/ph` with the
upload token and rate-limits it. Config/secrets live in ESP32 NVS (relay) and
`config.json` / env vars (Tilt Pi); `.gitignore` correctly excludes
`config.json` and `credentials.json`. The most sensitive surfaces are the two
network ingestion points (relay port 80, Tilt Pi 5000) and the shared upload
secret, and that is where the significant findings cluster.

## 3. Prioritized remediation plan (risk × effort)

**Do first — the relay is currently broken and leaks secrets:**
1. **CRIT-1** delete duplicate handlers so the firmware compiles. *~30 min.*
2. **CRIT-2** authenticate `/config` and stop rendering secrets. *~1–2 h.*
3. **HIGH-1** add `collectHeaders` so auth actually works. *~15 min* (do with CRIT-2; they're the same auth path).

**Then — the Sheets path doesn't work and the token is weakly handled:**
4. **HIGH-2** fix Google Apps Script auth (token in body/param, not header). *~1–2 h + redeploy.*
5. **MED-1** constant-time token compare. *~15 min.*
6. **MED-5** validate the timestamp on ingest. *~30 min.*
7. **MED-2** stop leaking exception text; correct status codes. *~30 min.*
8. **MED-4** quote/whitelist Tilt SQL identifiers. *~45 min.*
9. **MED-3** decide and document/enforce the read-endpoint trust boundary. *~1 h.*

**Cleanup (batch when convenient):** LOW-1…LOW-5. *~2 h total.*

## 4. Implementation prompts (one per finding above LOW)

Each prompt is self-contained for a downstream coding agent. Give it the cited
files. Do not change public behavior beyond what the prompt states.

### PROMPT CRIT-1 — remove duplicate handler definitions
**Problem:** `pHloat_Relay/pHloat_Relay_WebUI.ino` defines `handleData` twice
(lines ~107 and ~405) and `handleCalibration` twice (lines ~70 and ~182). Two
definitions of the same function in one Arduino sketch is a C++ redefinition
error, so the relay does not compile. The first of each pair is the current
version that loads HTML via `phloat_load_template(TPL_...)`; the second is stale
inline HTML left over from the Web-UI extraction refactor (commit `3ed8736`).
**Target file:** `pHloat_Relay/pHloat_Relay_WebUI.ino`.
**Required change:** delete the stale inline duplicates — the second
`handleData` (the `R"rawliteral(...)"` block starting ~line 405) and the second
`handleCalibration` (starting ~line 182) — keeping the template-loading versions
(~107 and ~70). Remove any now-unused inline HTML/helpers they referenced.
**Constraints:** do not touch the route table in `pHloat_Relay.ino:558-568`; the
kept handlers must still match those route names and signatures. Do not alter
`requireAuth` or any other handler.
**Acceptance:** `grep -c "void handleData" pHloat_Relay/pHloat_Relay_WebUI.ino`
== 1 and same for `handleCalibration`; the sketch compiles in Arduino IDE /
`arduino-cli compile` for the relay board with no redefinition error.

### PROMPT CRIT-2 — authenticate `/config` and stop emitting secrets
**Problem:** `handleConfig` (`pHloat_Relay/pHloat_Relay_WebUI.ino:47-63`) serves
`GET /config` with no auth and substitutes real secrets into the page:
`{{API_KEY}}` (`:59`), `{{UPLOAD_SECRET}}` (`:60`), `{{AP_PASSWORD}}` (`:57`),
`{{PMK}}` (`:58`). Anyone on the LAN or the relay SoftAP can read them.
**Target files:** `pHloat_Relay/pHloat_Relay_WebUI.ino`, and the config template
(`pHloat_Relay/web_ui_templates.h` / `web/relay/config.html`).
**Required change:** (a) call `if (!requireAuth()) return;` at the top of
`handleConfig` (depends on HIGH-1 being fixed so auth works). (b) Never render
secret values: replace `{{API_KEY}}`, `{{UPLOAD_SECRET}}`, `{{AP_PASSWORD}}`,
`{{PMK}}` with a masked indicator (e.g. `••••` or "set"/"unset") and change the
form fields to write-only "enter new value to change" inputs that, when left
blank on save, leave the stored secret unchanged. Non-secret fields
(`WIFI_SSID`, `NTP_SERVER`, `TIMEZONE_OFFSET`, `UPLOAD_URL`, enabled flags) may
still be shown.
**Constraints:** `handleSaveConfig` must preserve existing secrets when a
write-only field is submitted blank (do not overwrite with empty). Do not weaken
the WiFi/AP/ESP-NOW functionality. Keep the page usable without JS beyond what
exists.
**Acceptance:** `GET /config` without a valid `X-API-Key` returns 401 and no
secret appears in the body; with a valid key, the page shows masked secrets and
never the literal API key / upload secret / AP password / PMK. Saving config
with the secret fields blank leaves NVS values unchanged (verify by reading them
back).

### PROMPT HIGH-1 — register the auth header so `requireAuth` works
**Problem:** `requireAuth()` (`pHloat_Relay/pHloat_Relay_WebUI.ino:13-33`) uses
`server.hasHeader("X-API-Key")` / `server.header("X-API-Key")`, but the ESP32
`WebServer` only stores headers registered via `collectHeaders()`. No such call
exists before `server.begin()` (`pHloat_Relay.ino:140`), so custom headers are
invisible and `requireAuth` always 401s.
**Target file:** `pHloat_Relay/pHloat_Relay.ino` (in `setupWebServer`, before
`server.begin()`).
**Required change:** add
`const char *collectHeaders[] = {"X-API-Key"}; server.collectHeaders(collectHeaders, 1);`
(or the two-arg overload appropriate to the installed core) immediately before
`server.begin()`.
**Constraints:** do not change `requireAuth`'s logic; header name must stay
`X-API-Key`. Keep the fix minimal.
**Acceptance [VERIFY hardware]:** with the header registered, `POST /saveConfig`
with a correct `X-API-Key` succeeds (200) and with a wrong/missing key returns
403/401 — i.e. the write endpoints are usable again.

### PROMPT HIGH-2 — fix Google Apps Script auth (headers aren't available)
**Problem:** `GoogleAppsScript.js` authenticates by reading
`e.headers['X-pHloat-Token']` (`:29-30`, and `doGet` at `:207`). Apps Script web
apps do not pass request headers to `doPost`/`doGet`, so `supplied` is always
empty and every authenticated upload throws `Unauthorized`. The relay sends the
token as an HTTP header (`pHloat_Relay.ino:400`), which GAS cannot read.
**Target files:** `GoogleAppsScript.js`, `pHloat_Relay/pHloat_Relay.ino`
(upload function ~`:382-403`), `integration/upload_contract.json`.
**Required change:** move the token off the header onto data GAS *can* read:
for POST, include `"token": "<secret>"` in the JSON body and have
`verifyUploadToken_` read `JSON.parse(e.postData.contents).token`; for
`doGet`, read `e.parameter.token`. Update the relay: when the upload URL is a
GAS URL (`phloat_is_gas_upload_url`), add the token to the JSON body instead of
(or in addition to) the header; keep the header for the Tilt Pi path (which can
read headers). Update `upload_contract.json` to document the token field and
bump `version` to 2, and note the per-endpoint auth mechanism.
**Constraints:** do not break the Tilt Pi path (`tiltpi/phloat_upload.py`
reads the header and must keep working — so the relay still sends the header for
Tilt Pi URLs). Keep constant-time comparison (see MED-1). Do not log the token.
**Acceptance [VERIFY deploy]:** deploy the updated script; a POST with the token
in the body writes a row and returns `{"status":"success"}`; a POST with a wrong
/ missing token returns the error path; the relay's real upload to the GAS URL
succeeds end-to-end (a row appears in the sheet).

### PROMPT MED-1 — constant-time token comparison
**Problem:** `verify_upload_token` compares with `supplied != expected`
(`tiltpi/phloat_upload.py:26`); GAS uses `!==` (`GoogleAppsScript.js:31`). Both
are non-constant-time, leaking timing about the secret.
**Target files:** `tiltpi/phloat_upload.py`, `GoogleAppsScript.js`.
**Required change:** Python — `import hmac` and use
`hmac.compare_digest(supplied, expected)` (both `str`). GAS — implement a
constant-time compare (equal-length XOR-accumulate over char codes) and use it
for the token check.
**Constraints:** behavior identical for correct/incorrect tokens; still return
`(False, "Unauthorized")` on mismatch and `(False, "Upload secret not
configured")` when unset. Keep the existing tests green.
**Acceptance:** `tests/test_phloat_upload.py::test_verify_token` still passes;
add a test that a correct token returns `(True, None)` and an incorrect one
`(False, "Unauthorized")`.

### PROMPT MED-2 — stop leaking exception text; correct status codes
**Problem:** `receive_ph_data` (`tiltpi/phloat_server.py:406-411`) returns
`str(e)` to the client with HTTP 500, including validation failures that should
be 400.
**Target file:** `tiltpi/phloat_server.py`.
**Required change:** split the handler: catch `ValueError` (from
`validate_reading_payload`) and return `400` with a generic
`{"status":"error","message":"Invalid payload"}`; catch everything else, log the
full exception server-side (`print`/logging), and return `500` with a generic
`{"status":"error","message":"Internal error"}` — never `str(e)`.
**Constraints:** keep the auth (401/503) and rate-limit (429) branches and their
messages unchanged; keep the success response shape.
**Acceptance:** posting invalid JSON / out-of-range pH returns 400 with a
generic message and no stack/exception text; a forced internal error returns 500
generic; server logs still contain the real error.

### PROMPT MED-3 — decide and enforce the read-endpoint trust boundary
**Problem:** `/data`, `/api/recent`, `/api/status`, `/config`
(`tiltpi/phloat_server.py`) are unauthenticated and the server binds `0.0.0.0`
(`:502`). Anyone on the LAN can read all pH history and config.
**Target files:** `tiltpi/phloat_server.py`, `README.md` / `TILT_PI_INTEGRATION.md`.
**Required change:** pick one and implement it: (a) require the upload token
(via `verify_upload_token`) on the read endpoints too; or (b) add a config flag
`bind_host` (default `127.0.0.1`, opt-in `0.0.0.0`) and document that read
endpoints are unauthenticated LAN-trust. Document the chosen boundary in the
integration doc.
**Constraints:** `/api/ph` behavior unchanged; don't break the dashboard's
`fetch('/api/recent')` (if you add auth, the dashboard JS must send the token —
prefer option (b) if you want to keep the dashboard tokenless).
**Acceptance:** the documented boundary is enforced by code (either reads require
the token, or the bind host is configurable and defaults to loopback) and the
README states exactly who can reach what.

### PROMPT MED-4 — quote/whitelist Tilt SQL identifiers
**Problem:** `find_matching_tilt_reading` (`tiltpi/tilt_matching.py:44-51`)
builds SQL by f-string-interpolating table and column names discovered from the
Tilt DB. Parameter values are bound (good), but identifiers are not quoted or
validated.
**Target file:** `tiltpi/tilt_matching.py`.
**Required change:** validate each discovered identifier against the actual
column/table list already read from `PRAGMA table_info` / `sqlite_master`
(reject anything not in that set), and wrap identifiers in double quotes in the
query. Keep the bound `?` parameters for the epoch/window values.
**Constraints:** matching results must be identical for well-formed Tilt DBs;
only malformed/hostile schemas should now be rejected (return `None`, log a
warning). Keep the ±`TIME_MATCH_WINDOW` behavior.
**Acceptance:** matching still works against a normal Tilt DB (add a small test
with an in-memory SQLite Tilt table); an identifier containing SQL
meta-characters is rejected rather than interpolated.

### PROMPT MED-5 — validate the ingest timestamp
**Problem:** `validate_reading_payload` (`tiltpi/phloat_upload.py:43`) accepts
`timestamp` unvalidated; a malformed value is stored and silently breaks Tilt
matching. GAS already validates (`GoogleAppsScript.js:55-57`).
**Target file:** `tiltpi/phloat_upload.py`.
**Required change:** parse the timestamp (accept ISO-8601 and
`YYYY-MM-DD HH:MM:SS`, matching the contract); on failure either raise
`ValueError("Invalid timestamp")` or fall back to `datetime.now().isoformat()`
— choose raise for correctness, and normalize the stored value to ISO-8601.
**Constraints:** keep the `timestamp or now()` default for a *missing* field;
only reject a *present but unparseable* value. Keep the return tuple shape.
**Acceptance:** a present valid timestamp is normalized and returned; a present
invalid timestamp raises `ValueError` (→ 400 via MED-2); a missing timestamp
defaults to now. Add tests for all three.
